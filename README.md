# HacathonMax

Бот для платформы MAX, который помогает школьникам находить подходящие олимпиады и не пропускать важные сроки.

## Возможности

Бот позволяет:

- выбрать класс и интересующие предметы;
- подобрать подходящие олимпиады;
- подписаться на все подходящие олимпиады, олимпиады определённого уровня или выбрать их вручную;
- просматривать и изменять профиль;
- просматривать сохранённые олимпиады;
- просматривать все известные сроки олимпиад в хронологическом порядке;
- получать уведомления о начале регистрации и этапов;
- получать уведомления за 3 дня до окончания регистрации и этапов.

В настоящий момент в базе представлены олимпиады по математике и информатике. Поддержка остальных предметов предусмотрена интерфейсом и может быть расширена наполнением базы данных.

## Команды

- `/start` — первоначальная настройка или повторная настройка профиля;
- `/profile` — просмотр профиля, олимпиад и сроков;
- `/info` — информация о боте и доступных командах.

## Архитектура

Приложение построено по слоистой архитектуре:

- `api` — взаимодействие с MAX Bot API;
- `bot` — обработка сообщений пользователя, callback-событий и формирование inline-клавиатур;
- `services` — бизнес-логика приложения;
- `repositories` — слой доступа к данным;
- `models` — модели SQLAlchemy;
- `database` — создание и настройка подключения к PostgreSQL.

Основные компоненты:

1. `Bot` получает события из MAX Bot API.
2. `MessageHandler` обрабатывает текстовые команды пользователя.
3. `CallbackHandler` обрабатывает действия с клавиатурами.
4. `UserService` управляет профилем пользователя и его подписками.
5. `OlympiadService` выполняет подбор олимпиад и работу с ними.
6. `NotificationWorker` периодически проверяет сроки и запускает отправку уведомлений.
7. PostgreSQL хранит пользователей, олимпиады, предметы, этапы, подписки и историю уведомлений.

Взаимодействие с MAX выполняется через `MaxClient`.

## Быстрый запуск через Docker

Для запуска необходимы:

- Git;
- Docker Desktop;
- токен бота MAX.

### 1. Клонирование проекта

```bash
git clone https://github.com/ISich/HacathonMax_olimpiad_notificator.git
cd HacathonMax
```

### 2. Настройка окружения

Создайте файл `.env` на основе `.env.example`.

Пример:

```env
MAX_TOKEN=your_max_bot_token
```

`MAX_TOKEN` необходимо заменить на токен вашего бота MAX.

Файл `.env` содержит секретные данные и не должен добавляться в Git.

### 3. Запуск

```bash
docker compose up --build
```

При запуске автоматически:

1. создаётся контейнер PostgreSQL;
2. ожидается готовность базы данных;
3. применяются миграции Alembic;
4. база заполняется предметами и олимпиадами из `data/OlimpiadData.xlsx`;
5. запускается бот.

После появления сообщения:

```text
Бот запущен. Жду сообщения...
```

бот готов к работе.

### Остановка

Для остановки нажмите `Ctrl+C`, затем выполните:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `postgres_data`.

Для удаления контейнеров вместе с данными:

```bash
docker compose down -v
```

### Повторный запуск

После остановки проекта повторный запуск выполняется командой:

```bash
docker compose up
```

Если исходный код или зависимости были изменены:

```bash
docker compose up --build
```

Данные пользователей и олимпиад сохраняются в Docker volume и доступны после повторного запуска.

Для полного сброса данных:

```bash
docker compose down -v
docker compose up --build
```

## Локальный запуск без Docker

Для локальной разработки необходимы:

- Python;
- PostgreSQL;
- Git.

### 1. Создание виртуального окружения

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Создание баз PostgreSQL

Создайте две базы данных:

```sql
CREATE DATABASE hackathon_max;
CREATE DATABASE hackathon_max_test;
```

### 4. Настройка `.env`

Создайте `.env` на основе `.env.example`:

```env
MAX_TOKEN=your_max_bot_token
DATABASE_URL=postgresql+psycopg://postgres:your_password@localhost:5432/hackathon_max
TEST_DATABASE_URL=postgresql+psycopg://postgres:your_password@localhost:5432/hackathon_max_test
```

Замените `your_password` на пароль локального пользователя PostgreSQL.

### 5. Применение миграций

```bash
alembic upgrade head
```

### 6. Заполнение базы данных

```bash
python -m scripts.setup_database
```

Скрипт:

- добавляет предметы;
- загружает олимпиады из `data/OlimpiadData.xlsx`;
- создаёт связи олимпиад с предметами, классами и этапами.

Скрипт можно запускать повторно: существующие олимпиады обновляются по `external_id`.

### 7. Запуск бота

```bash
python -m app.main
```

## Работа с данными

Исходные данные об олимпиадах находятся в:

```text
data/OlimpiadData.xlsx
```

При первоначальном запуске `scripts.setup_database` загружает данные в PostgreSQL.

Для олимпиад хранятся данные, необходимые для работы сервиса, включая:

- название;
- уровень;
- подходящие классы;
- предметы;
- этапы;
- сроки регистрации;
- сроки проведения этапов;
- внешний идентификатор.

Пользовательские данные включают:

- идентификатор пользователя MAX;
- идентификатор чата;
- выбранный класс;
- выбранные предметы;
- подписки на олимпиады;
- историю отправленных уведомлений.

В текущей версии используется заранее подготовленный набор данных об олимпиадах. Прямой интеграции с информационными системами организаторов олимпиад нет.

## Внешние сервисы и интеграции

Проект использует:

- MAX Bot API — получение сообщений и callback-событий, отправка сообщений и управление командами бота;
- PostgreSQL — постоянное хранение данных.

Получение событий от MAX реализовано через long polling.

Собственного публичного HTTP API проект не предоставляет.

Данные об олимпиадах в текущей версии не загружаются автоматически из внешних сервисов и поставляются вместе с проектом.

## Используемые порты

В Docker-конфигурации PostgreSQL используется внутри сети Docker Compose.

Бот не предоставляет собственного HTTP API и не требует открытия входящего HTTP-порта.

Взаимодействие с MAX Bot API выполняется исходящими HTTPS-запросами.

## Уведомления

Бот отслеживает сроки сохранённых пользователем олимпиад.

Уведомления формируются:

- в день начала регистрации;
- за 3 дня до окончания регистрации;
- в день начала этапа;
- за 3 дня до окончания этапа.

История отправленных уведомлений сохраняется в базе данных, поэтому одно и то же уведомление повторно не отправляется.

Для ручной проверки отправки уведомлений используется:

```bash
python -m scripts.send_notifications
```

## Сценарий проверки

После запуска проекта откройте чат с ботом в MAX.

### Основной сценарий

1. Отправьте `/start`.
   - Бот предложит выбрать класс.

2. Выберите класс.
   - Бот предложит выбрать интересующие предметы.

3. Выберите математику и/или информатику и нажмите «Готово».
   - Для остальных предметов отображается отметка `⏳`, так как данные по ним пока отсутствуют.

4. Выберите способ подписки:
   - все подходящие олимпиады;
   - по уровню;
   - конкретные олимпиады.

5. Завершите выбор.
   - Бот сохранит выбранные олимпиады пользователя.

6. Отправьте `/profile`.
   - Бот покажет выбранный класс и предметы.
   - Из профиля доступны изменение класса, изменение предметов, просмотр олимпиад и просмотр всех сроков.

7. Нажмите «Мои олимпиады».
   - Бот покажет сохранённые олимпиады.
   - Отдельную олимпиаду можно удалить из подписок.

8. Нажмите «📅 Все сроки».
   - Бот покажет известные сроки сохранённых олимпиад в хронологическом порядке.
   - События без определённой даты выводятся отдельно.

9. Отправьте `/info`.
   - Бот покажет описание сервиса и доступные команды.

10. Отправьте произвольный неизвестный текст.
    - Бот сообщит, что команда не распознана, и предложит использовать `/start` или `/info`.


## Известные ограничения

Текущая версия MVP имеет следующие ограничения:

- база содержит олимпиады только по математике и информатике;
- данные об олимпиадах загружаются из подготовленного файла и не синхронизируются автоматически с сайтами организаторов;
- полнота отображаемых сроков зависит от полноты исходных данных;
- если для события невозможно определить конкретную дату, оно отображается отдельно от хронологического списка;
- бот использует long polling, а не webhook;
- мини-приложение MAX в текущей версии не используется;
- уведомления зависят от сохранённых в базе сроков.
